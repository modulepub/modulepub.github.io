### 還有一類：高頻、輕量的社區商業

原型中還有“拾光咖啡聯盟”“鄰里互助社”“織造工坊聯營”等項目。它們共同説明：

- 社區項目不必都是“硬科技”；
- 小體量項目也可以通過透明的票據與任務結構建立信任；
- “明星”不等於“最大”，而是“結構最清楚、最容易被複制”。

## 二、五個共同點

### 1. 目標可拆，不是一句口號

每個項目都從根節點開始，拆成子項目 / 目標，再拆成成果與任務。

```text
項目（root）
├── 子項目 / 分支（branch）
│   ├── 目標（goal）
│   │   ├── 成果（outcome）
│   │   │   └── 任務（task）
│   │   └── 成果（outcome）
│   └── 目標（goal）
└── ...
```

這棵樹的價值不在於“好看”，而在於**每一個任務都能回溯到它服務的成果，每一個成果都能回溯到項目目標**。

### 2. 任務有成本，成本有口徑

任務支持兩種回報口徑：

- **給票**：以票權額結算；
- **現金**：以人民幣金額結算。

項目樹同時彙總計票支出、計票收入、現金支出、現金收入與計劃成本。
這讓“錢花在哪、換回了什麼”不再是一筆糊塗賬。

### 3. 財務可核查

項目詳情可以進入透明財務、投入明細、收入明細、票據份額與流水。
關鍵不是“有報表”，而是報表能對上：

- 投入與票據的對應關係；
- 任務成本與成果的對應關係；
- 分紅 / 結算與持票人的對應關係。

### 4. 份額可流轉，但不是證券

原型提供票據轉讓能力，但是否可轉讓、如何定價、如何合規，必須由項目規則與當地法律共同約束。
**技術上的可轉讓，不等於法律上的可發行。**

### 5. 公共性有位置

項目類型分為：

| 類型 | 含義 |
| --- | --- |
| 全公益項目 | 全部收益用於公益目的 |
| 輕公益項目 | 運營滿 10 年後須退還投入並捐獻給政府 |
| 私有項目 | 不進路演池，僅創建者與持票人可見 |

公共性不是成功之後的“可選項”，而是在項目創建時就要選擇的類型。

## 三、一個樣板項目的完整讀法

以“青禾智慧農場”為例：

1. **先看根節點**：項目解決什麼問題？為什麼是冷鏈，而不是別的？
2. **再看目標**：冷鏈共建、社區團購閉環，分別對應什麼可驗證的結果？
3. **再看成果**：縣域冷鏈倉、線路開通、溯源看板，是否真的支撐目標？
4. **再看任務**：倉租、製冷設備、冷藏車、IoT 探針，每一項的成本與負責人是誰？
5. **最後看賬**：投入、收入、票權、分紅是否對得上？

如果這五步有任何一步説不清，項目就還不適合被複制。

## 四、從樣板到複製：六個檢查

<ul class="doc-checklist">
  <li>項目是否有明確的本地運營主體與合規路徑？</li>
  <li>目標是否可以拆成可驗收的成果與任務？</li>
  <li>每一項任務是否有成本口徑、負責人和完成標準？</li>
  <li>收入與分紅是否有可核查的賬本，而不是隻有彙總數字？</li>
  <li>項目類型（全公益 / 輕公益 / 私有）是否在創建時説明？</li>
  <li>如果失敗，退出、清算與責任如何安排？</li>
</ul>
