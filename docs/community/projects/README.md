### 还有一类：高频、轻量的社区商业

原型中还有“拾光咖啡联盟”“邻里互助社”“织造工坊联营”等项目。它们共同说明：

- 社区项目不必都是“硬科技”；
- 小体量项目也可以通过透明的票据与任务结构建立信任；
- “明星”不等于“最大”，而是“结构最清楚、最容易被复制”。

## 二、五个共同点

### 1. 目标可拆，不是一句口号

每个项目都从根节点开始，拆成子项目 / 目标，再拆成成果与任务。

```text
项目（root）
├── 子项目 / 分支（branch）
│   ├── 目标（goal）
│   │   ├── 成果（outcome）
│   │   │   └── 任务（task）
│   │   └── 成果（outcome）
│   └── 目标（goal）
└── ...
```

这棵树的价值不在于“好看”，而在于**每一个任务都能回溯到它服务的成果，每一个成果都能回溯到项目目标**。

### 2. 任务有成本，成本有口径

任务支持两种回报口径：

- **给票**：以票权额结算；
- **现金**：以人民币金额结算。

项目树同时汇总计票支出、计票收入、现金支出、现金收入与计划成本。
这让“钱花在哪、换回了什么”不再是一笔糊涂账。

### 3. 财务可核查

项目详情可以进入透明财务、投入明细、收入明细、票据份额与流水。
关键不是“有报表”，而是报表能对上：

- 投入与票据的对应关系；
- 任务成本与成果的对应关系；
- 分红 / 结算与持票人的对应关系。

### 4. 份额可流转，但不是证券

原型提供票据转让能力，但是否可转让、如何定价、如何合规，必须由项目规则与当地法律共同约束。
**技术上的可转让，不等于法律上的可发行。**

### 5. 公共性有位置

项目类型分为：

| 类型 | 含义 |
| --- | --- |
| 全公益项目 | 全部收益用于公益目的 |
| 轻公益项目 | 运营满 10 年后须退还投入并捐献给政府 |
| 私有项目 | 不进路演池，仅创建者与持票人可见 |

公共性不是成功之后的“可选项”，而是在项目创建时就要选择的类型。

## 三、一个样板项目的完整读法

以“青禾智慧农场”为例：

1. **先看根节点**：项目解决什么问题？为什么是冷链，而不是别的？
2. **再看目标**：冷链共建、社区团购闭环，分别对应什么可验证的结果？
3. **再看成果**：县域冷链仓、线路开通、溯源看板，是否真的支撑目标？
4. **再看任务**：仓租、制冷设备、冷藏车、IoT 探针，每一项的成本与负责人是谁？
5. **最后看账**：投入、收入、票权、分红是否对得上？

如果这五步有任何一步说不清，项目就还不适合被复制。

## 四、从样板到复制：六个检查

<ul class="doc-checklist">
  <li>项目是否有明确的本地运营主体与合规路径？</li>
  <li>目标是否可以拆成可验收的成果与任务？</li>
  <li>每一项任务是否有成本口径、负责人和完成标准？</li>
  <li>收入与分红是否有可核查的账本，而不是只有汇总数字？</li>
  <li>项目类型（全公益 / 轻公益 / 私有）是否在创建时说明？</li>
  <li>如果失败，退出、清算与责任如何安排？</li>
</ul>
