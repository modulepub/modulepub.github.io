<div class="doc-eyebrow">SHOWCASE · REPLICABLE, NOT JUST IMPRESSIVE</div>

<p class="doc-lead">
  这里的“明星”不以估值、流量或融资额为标准，而以<strong>结构是否可复制</strong>为标准。
  下面六个项目不是策划案里的样板，而是众联共识平台项目中心里正在路演的真实项目：
  它们各自只有一名创建者，拆解的深度也不一样：有的拆到主线，有的只拆到任务，但都已经把第一笔票记进了账本。
</p>

::: warning 数据说明
以下项目与数字取自社区 uni-app 工程（`uniapp-project`）所连接的众联共识平台项目库，统计截至 2026-10-23。
“已计票”指创建者完成自挂任务后获得的票据，“任务合计”是该根项目下所有任务的消费票数之和。
票据是任务与票权的计量单位，不是证券，也不代表真实融资、经营业绩或任何收益承诺。
:::

本节的项目树、任务、票据与账本，与平台里的路演大厅、任务大厅、白皮书和 GCC 工作台共用一套数据。
技术实现服务于一个目标：**让项目的目标、任务、资金与治理关系可以被同一个界面读懂。**

六个项目里，五个在 2026-08-30 上架路演，捎着是 2026-10-15；目前各自只有 1 名创建者：创建者用自挂任务完成了第一次计票，其余任务仍在开放认领。

### 另外四个：同一套结构的不同行业

平台项目中心里还有四个项目，行业不同，拆法一样：

- **旺达社区能量站**（生活服务）：社区食堂承包家庭厨房，太空舱为旅人与务工者提供低价住宿，餐食与住宿拆成两条可核验的线；
- **公益免费医疗**（医疗健康）：先鉴定受助人准入条件再发起互助，帮扶人累积的公益贡献金记录社会价值；
- **【IP】柴道煌（户外牵）**（义卖扶贫）：以月老人设在景区与线上做真人免费牵线、促成；
- **【IP】楚门**（义卖扶贫）：用纪实访谈与「以小博大」创业挑战，记录真实人生故事。

它们共同说明：

- 社区项目不必都是“硬科技”；
- 项目不必等体量变大才开始透明，小体量也可以先有票据与任务结构；
- “明星”不等于“最大”，而是“结构最清楚、最容易被复制”。

## 二、五个共同点

### 1. 目标可拆，不是一句口号

每个项目都从根节点开始往下拆：大多数拆成子项目 / 主线，再拆成任务；拆得浅的项目，任务直接挂在根节点下。

```text
项目（root）
├── 子项目 / 主线（branch）
│   ├── 任务（task）        ← 五个项目当前的实际深度
│   └── 成果（outcome）     ← 需要验收口径时再加
│       └── 任务（task）
├── 任务（task）            ← 捎着：跳过主线，直接挂任务
└── ...
```

除捎着外，其余五个项目都拆到「项目 → 主线 → 任务」三层；捎着更浅，四个任务直接挂在根节点下。
拆得浅不一定是缺点，但它意味着可读性更依赖任务命名本身。需要对外验收时，再在主线与任务之间加一层成果。
这棵树的价值不在于“好看”，而在于**每一个任务都能回溯到它服务的上游节点，每一条主线都能回溯到项目目标**。

### 2. 任务有成本，成本有口径

平台当前的换算是：

> **1 元任务价值 = 1 票据 = 1 票权**

任务支持两种回报口径：

- **给票**：以票权额结算；
- **现金**：以人民币金额结算。

任务完成才计票，票据进入持票加权共治。项目树同时汇总计票支出、计票收入、现金支出、现金收入与计划成本。
这让“钱花在哪、换回了什么”不再是一笔糊涂账。

### 3. 财务可核查

项目详情可以进入透明财务、投入明细、收入明细、票据份额与流水。
关键不是“有报表”，而是报表能对上：

- 投入与票据的对应关系；
- 任务成本与主线的对应关系；
- 分红 / 结算与持票人的对应关系。

### 4. 份额可流转，但不是证券

平台提供票据转让能力，但是否可转让、如何定价、如何合规，必须由项目规则与当地法律共同约束。
**技术上的可转让，不等于法律上的可发行。**

### 5. 公共性有位置

项目类型分为：

| 类型 | 含义 |
| --- | --- |
| 全公益项目 | 全部收益用于公益目的 |
| 轻公益项目 | 运营满 10 年后须退还投入并捐献给政府 |
| 私有项目 | 不进路演池，仅创建者与持票人可见 |

公共性不是成功之后的“可选项”，而是在项目创建时就要选择的类型。上面六个项目都选择了「全公益」。

## 三、一个样板项目的完整读法

以“在线智慧生态农场”为例：

1. **先看根节点**：项目解决什么问题？为什么是“科学种田 + 游戏化”，而不是直接扩产？
2. **再看主线**：科学种田、游戏化农场、农户增收，各自承诺了什么可验证的结果？
3. **再看任务**：农田传感器与农事日历、QQ 农场玩法映射、农户分成规则、首季作物试点，是否真的支撑这三条线？
4. **再看成本**：每个任务 8–13 票的消费口径，谁认领、完成标准是什么？
5. **最后看账**：创建者自挂 13 票、任务合计 51 票，票据与任务是否对得上？

如果这五步有任何一步说不清，项目就还不适合被复制。

## 四、从样板到复制：七个检查

<ul class="doc-checklist">
  <li>项目是否有明确的本地运营主体与合规路径？</li>
  <li>目标是否可以拆成可验收的主线与任务？</li>
  <li>每一项任务是否有成本口径、负责人和完成标准？</li>
  <li>“1 元任务价值 = 1 票据 = 1 票权”这条换算，是否在项目里写清楚？</li>
  <li>收入与分红是否有可核查的账本，而不是只有汇总数字？</li>
  <li>项目类型（全公益 / 轻公益 / 私有）是否在创建时说明？</li>
  <li>如果失败，退出、清算与责任如何安排？</li>
</ul>
