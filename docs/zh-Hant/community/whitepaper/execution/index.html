執行與邊界

约 1823 字大约 6 分钟

EXECUTION · RULES BEFORE NARRATIVE

白皮書負責解釋“為什麼”，這一頁負責説明“到底怎麼執行、哪裏會失敗、什麼不在合約裏”。 它更像一份技術附件：不寫願景，只寫邊界。

交互前先核實

合約地址、部署網絡、審計狀態與前端入口，請以倉庫中的 deployments 文件、官方公告和鏈上瀏覽器為準。 不要在未核實的地址上授權、轉賬或質押。

一、本期鏈上已定的關鍵規則

  1. 創始人部署時即在任代理與在位擔保；代理地址一旦寫入不可更換；合約沒有暫停開關。
  2. 社區利潤注入時，金額的 1/3 進入股本池，其餘按質押票權分配。
  3. 任何人捐入的分紅，100% 按質押票權分配；沒有單獨切給擔保人的 30%。
  4. 票權 = 數量 × 該倉位與賬單重疊的秒數；擔保價大於 0 的重疊秒數，係數為 2。
  5. 賬單區間內只有一個地址有票權，該地址拿走全部；一個地址都沒有，進入股本池。
  6. 分紅記入可領取，由本人領取；不在入賬時直接轉賬。
  7. 最小質押 1 GCC；普通質押人自寫可解除時間；擔保人的質押要等破產清算或創業成功之後才能解除。
  8. 破產、創業成功、終止代理、股本借用：合格質押地址 一人一票。
  9. 新擔保人須有一筆連續滿 1 年且仍在押的質押，再鎖入大於 0 的擔保價。
  10. 破產的唯一發起條件：有公價賣單掛滿 1 年仍未兑完；投票 7 天。
  11. 創業成功的條件：股本池至少 2 億 USDT；投票 7 天；贊成多於反對；外部仍有 GCC。
  12. 創業成功執行時，把股本池全部 USDT 按持有量贈送，並清退全部擔保、退回擔保價。
  13. 公價賣單和買單都由股本池或庫存按隊列處理，可以拆開成交；不提供私價買賣與二級市場。
  14. 本土貨幣不進合約，由代理在當地按票權支付，持有人自行確認到賬。
  15. 創業成功後的富餘紅利可按金價記為積分，1 積分錨定 1 克黃金；積分可轉賬。
  16. 終止代理只能在創業成功之後發起；通過後代理地址清空，合約不改寫新地址，也不劃轉資產。

二、角色與接口

2.1 持有人

接口作用主要失敗條件
deposit(amount)支付 USDT，從庫存取得 GCC庫存不足、USDT 未到賬、數量為 0
redeem(amount)進入公價賣單隊尾，按隊列兑付GCC 未到賬、數量為 0
placePublicSell(amount)從錢包掛公價賣單GCC 未到賬、數量為 0
placePublicBuy(amount)按機制定價鎖定 USDT，從庫存成交USDT 未到賬、數量為 0
cancelOrder(orderId)撤賣單，剩餘 GCC 回錢包非本人、非排隊中、已破產

2.2 代理公司

接口作用
contribute(amount, periodStart, periodEnd)注入淨額；1/3 進股本池，其餘按票權
requestEquityWithdraw(amount)申請股本借用，投票 7 天
GccProjectCatalog.publish(...)發佈社區項目目錄

2.3 擔保公司

接口作用
bidGuarantee(amount)鎖入或追加擔保價
releaseGuarantor()破產後嘗試兑完所有賣單，再解除身份
voteEquityWithdraw(requestId, yes)對股本借用投票
executeEquityWithdraw(requestId)截止後按結果執行

擔保份額只用於鏈下商量，不改變鏈上借用的一人一票，也不用於鏈上分紅。

三、鏈上狀態

狀態含義
inventory合約內尚未放出的庫存

buyLocked未成交買單鎖定的 USDT

恆等式：

總供應 = 庫存 + 流通量 + 賣單量 + 質押量 = 200,000,000
對外債權 = 流通量 + 賣單量 + 質押量 = 總供應 − 庫存
合約託管 USDT = 股本池 + 分紅池 + 擔保池鎖定

四、失敗與邊界

4.1 兑出失敗不是“系統故障”

當股本池不足以支付整筆兑出時，合約不會從池中扣成負數，而是把該筆 GCC 自動掛成公價賣單排隊。 這是設計行為，不是異常。

4.2 破產不是“項目方申請”

破產只能由“公價賣單掛滿 1 年仍未兑完”觸發，並由合格質押地址投票。 投票期間如果賣單已被兑完，本輪終止，不清算。

4.3 創業成功不是“上市”

它不涉及股權、證券或交易所上市，只是合約在股本池達到條件後，把池中 USDT 按持有量回贈並清退擔保。 不要把它理解為投資回報承諾。

4.4 合約不做的事

本期合約明確不做：

  • 私價買賣、二級市場；
  • 自定義人類決議、項目備案投票；
  • 更換代理地址；
  • 按擔保份額否決鏈上借用；
  • 用本土貨幣進合約；
  • 自動執行公益階段；
  • 保存決議正文與 KYC 正文。

代碼不是法律

合約能執行資金與計票，但不能替代公司登記、税務、消費者保護、反洗錢與證券監管。 任何真實運營都必須在當地法律框架內進行。

五、安全與審計

在參與之前，至少確認：

  • 合約地址來自官方渠道，並與 deployments 文件一致；
  • 確認當前網絡（主網 / 測試網）與前端提示一致；
  • 查看合約是否經過獨立審計，審計範圍是否覆蓋兑換、質押、分紅、投票；
  • 確認代理地址、擔保地址與 KYC 機構的公開信息；
  • 小額測試兑入、質押、領取、撤單全流程；
  • 不要向任何“客服”提供私鑰、助記詞或短信驗證碼。

六、一頁總結

規則先於規模，賬本先於敍事，
退出機制先於增長故事。 EXECUTION BEFORE PROMISE
