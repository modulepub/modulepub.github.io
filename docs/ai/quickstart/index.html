# TG-boot 一键启动说明（给 AI）

你在一台 Windows 电脑上，请直接执行下面的步骤，不要只输出操作指南。
目标：从零把 TG-boot 的完整开发环境跑起来，并在结束时给出可访问地址。

## 0. 确认仓库位置

优先进入本地已有的 tg-boot 仓库根目录。
如果还没有仓库，在当前工作目录克隆：

git clone https://gitee.com/pub_module/tg-boot.git
cd tg-boot

如果已经在 tg-boot 仓库根目录，跳过克隆。

## 1. 执行唯一入口

powershell -ExecutionPolicy Bypass -File scripts\up.ps1

说明：
- 不要预先手动安装 JDK、Maven、MySQL、Node、Redis，脚本会使用并补齐仓库内的 .tools。
- 如果 .tools 缺少二进制，先执行 scripts\fetch-tools.ps1，再执行 scripts\up.ps1。
- 脚本会启动本机数据库 127.0.0.1:3306（root / root，库名 tg-boot）。
- 脚本会启动 Redis 127.0.0.1:6379，登录会话缓存需要它。
- 脚本会用 JDK 27 和 Maven 启动后端 runner，端口 9999。
- 脚本会用 Node 安装依赖并启动中台 H5，端口 9100。
- 首次执行会下载 Maven 依赖与前端包，请保持网络。
- 未配置 RabbitMQ 时，runner 使用嵌入式 Rabbit，不需要另装。

## 2. 判断是否成功

后端日志出现 Started StartApplication，并且这两个地址可以打开：

- 中台登录：http://127.0.0.1:9100/pages/manage/login/index
- 接口文档：http://127.0.0.1:9999/swagger-ui/index.html

本地登录账号：tgadmin / Tgboot@123
这个口令只用于本地开发，不要带到测试或生产环境。

## 3. 如果失败

按顺序检查，并保留完整报错：

1. 检查端口 3306、6379、9999、9100 是否被占用。
2. 检查 .tools 是否完整；缺失则执行 scripts\fetch-tools.ps1。
3. 检查数据库是否已初始化；空库时脚本会导入 sql/tg-boot.sql 与 sql/local-login.sql。
4. 如果 Redis 未启动，登录会话会失败，先确认 127.0.0.1:6379 可连接。
5. 如果 Maven 报模块找不到，确认在仓库根目录执行，并保留 -am 参数。
6. 不要修改业务代码，不要提交 .tools/mysql-data，不要把本地口令带到生产。

如果仍然失败，输出：失败步骤、完整错误、已经尝试的修复、下一步建议。

## 4. 交付

执行完成后，用一句话报告状态，并返回上面的两个地址和登录账号。
请实际执行并验证，不要只给命令让我自己执行。

粘贴后让 AI 直接执行脚本，不要只让它输出步骤。完成后应返回 9100 与 9999 两个地址。

一、AI 会替你完成什么

这段说明不是“操作建议”，而是一份可执行的启动契约。AI 需要实际运行脚本，而不是把命令再转述给你。

步骤实际动作
准备运行时检查并补齐 .tools 中的 JDK、Maven、数据库、Node 与 Redis
初始化数据库启动本机数据库，空库时导入 sql/tg-boot.sql 与本地登录数据
启动缓存启动 Redis，供登录会话使用
启动后端用 JDK 27 + Maven 启动 runner，端口 9999
启动前端用 Node 安装依赖并启动中台 H5，端口 9100
验证交付检查日志、访问两个地址，并报告实际状态

这不是“远程一键部署”

脚本运行在你指定的这台 Windows 电脑上。它不会替你购买服务器、配置域名或部署到公网。 它解决的是：把本地完整开发环境从零建立起来。

二、你只需要做三件事

  1. 打开一个能执行 PowerShell 的 AI 编码工具，并让它进入 tg-boot 仓库根目录；
  2. 点击上面的 “复制给 AI”；
  3. 把整段说明粘贴给 AI，发送，然后等它执行并返回地址。

如果 AI 只输出了步骤而没有执行，补一句：

请直接执行，不要只给步骤。你可以运行 PowerShell 命令，并在每一步后检查实际输出。

三、成功标准

后端日志中出现：

Started StartApplication

并且这两个地址可以访问：

用途地址
中台登录http://127.0.0.1:9100/pages/manage/login/index
接口文档http://127.0.0.1:9999/swagger-ui/index.html

本地账号：tgadmin / Tgboot@123。

本地口令不要外带

这组账号来自本地初始化数据，只用于打开开发环境。 不要用于测试环境、生产环境，也不要把本地数据库快照直接当成生产数据。

四、如果 AI 卡住了

让 AI 按这个顺序排查，并把完整报错发回来：

现象优先检查
后端启动失败数据库是否启动、3306 是否被占用
登录后接口 401Redis 是否在 127.0.0.1:6379 运行
Maven 找不到模块是否在仓库根目录执行，是否保留 -am
端口冲突3306、6379、9999、9100 是否被旧进程占用
前端请求失败.env.development 的后端地址是否为 9999
RabbitMQ 连接失败是否误配了 spring.rabbitmq.*；开发环境默认使用嵌入式 Rabbit

只需给 AI 一句话

把“失败步骤 + 完整错误 + 已经尝试的修复”发给它，让它继续排查。 不要只发最后一行日志，最早出现的 Caused by 通常才是根因。

五、人工兜底

只有在 AI 无法执行命令、或你明确想手动接管时，才需要看这一节。

git clone https://gitee.com/pub_module/tg-boot.git
cd tg-boot
powershell -ExecutionPolicy Bypass -File scripts\up.ps1

如果 .tools 缺少运行时：

powershell -ExecutionPolicy Bypass -File scripts\fetch-tools.ps1
powershell -ExecutionPolicy Bypass -File scripts\up.ps1

已有数据库和 Redis 时，也可以单独启动后端：

powershell -ExecutionPolicy Bypass -File scripts\run-runner.ps1

这些命令只是兜底。正常路径是：复制说明给 AI，让 AI 执行并验证。

六、下一步

环境起来之后，不要停在登录页。先让 AI 做一次只读分析，再进入真实模块开发。
