# TG-boot 一鍵啓動説明（給 AI）

你在一台 Windows 電腦上，請直接執行下面的步驟，不要只輸出操作指南。
目標：從零把 TG-boot 的完整開發環境跑起來，並在結束時給出可訪問地址。

## 0. 確認倉庫位置

優先進入本地已有的 tg-boot 倉庫根目錄。
如果還沒有倉庫，在當前工作目錄克隆：

git clone https://gitee.com/pub_module/tg-boot.git
cd tg-boot

如果已經在 tg-boot 倉庫根目錄，跳過克隆。

## 1. 執行唯一入口

powershell -ExecutionPolicy Bypass -File scripts\up.ps1

説明：
- 不要預先手動安裝 JDK、Maven、MySQL、Node、Redis，腳本會使用並補齊倉庫內的 .tools。
- 如果 .tools 缺少二進制，先執行 scripts\fetch-tools.ps1，再執行 scripts\up.ps1。
- 腳本會啓動本機數據庫 127.0.0.1:3306（root / root，庫名 tg-boot）。
- 腳本會啓動 Redis 127.0.0.1:6379，登錄會話緩存需要它。
- 腳本會用 JDK 27 和 Maven 啓動後端 runner，端口 9999。
- 腳本會用 Node 安裝依賴並啓動中台 H5，端口 9100。
- 首次執行會下載 Maven 依賴與前端包，請保持網絡。
- 未配置 RabbitMQ 時，runner 使用嵌入式 Rabbit，不需要另裝。

## 2. 判斷是否成功

後端日誌出現 Started StartApplication，並且這兩個地址可以打開：

- 中台登錄：http://127.0.0.1:9100/pages/manage/login/index
- 接口文檔：http://127.0.0.1:9999/swagger-ui/index.html

本地登錄賬號：tgadmin / Tgboot@123
這個口令只用於本地開發，不要帶到測試或生產環境。

## 3. 如果失敗

按順序檢查，並保留完整報錯：

1. 檢查端口 3306、6379、9999、9100 是否被佔用。
2. 檢查 .tools 是否完整；缺失則執行 scripts\fetch-tools.ps1。
3. 檢查數據庫是否已初始化；空庫時腳本會導入 sql/tg-boot.sql 與 sql/local-login.sql。
4. 如果 Redis 未啓動，登錄會話會失敗，先確認 127.0.0.1:6379 可連接。
5. 如果 Maven 報模塊找不到，確認在倉庫根目錄執行，並保留 -am 參數。
6. 不要修改業務代碼，不要提交 .tools/mysql-data，不要把本地口令帶到生產。

如果仍然失敗，輸出：失敗步驟、完整錯誤、已經嘗試的修復、下一步建議。

## 4. 交付

執行完成後，用一句話報告狀態，並返回上面的兩個地址和登錄賬號。
請實際執行並驗證，不要只給命令讓我自己執行。

粘貼後讓 AI 直接執行腳本，不要只讓它輸出步驟。完成後應返回 9100 與 9999 兩個地址。

一、AI 會替你完成什麼

這段説明不是“操作建議”，而是一份可執行的啓動契約。AI 需要實際運行腳本，而不是把命令再轉述給你。

步驟實際動作
準備運行時檢查並補齊 .tools 中的 JDK、Maven、數據庫、Node 與 Redis
初始化數據庫啓動本機數據庫，空庫時導入 sql/tg-boot.sql 與本地登錄數據
啓動緩存啓動 Redis，供登錄會話使用
啓動後端用 JDK 27 + Maven 啓動 runner，端口 9999
啓動前端用 Node 安裝依賴並啓動中台 H5，端口 9100
驗證交付檢查日誌、訪問兩個地址，並報告實際狀態

這不是“遠程一鍵部署”

腳本運行在你指定的這台 Windows 電腦上。它不會替你購買服務器、配置域名或部署到公網。 它解決的是：把本地完整開發環境從零建立起來。

二、你只需要做三件事

  1. 打開一個能執行 PowerShell 的 AI 編碼工具，並讓它進入 tg-boot 倉庫根目錄；
  2. 點擊上面的 “複製給 AI”；
  3. 把整段説明粘貼給 AI，發送，然後等它執行並返回地址。

如果 AI 只輸出了步驟而沒有執行，補一句：

請直接執行，不要只給步驟。你可以運行 PowerShell 命令，並在每一步後檢查實際輸出。

三、成功標準

後端日誌中出現：

Started StartApplication

並且這兩個地址可以訪問：

用途地址
中台登錄http://127.0.0.1:9100/pages/manage/login/index
接口文檔http://127.0.0.1:9999/swagger-ui/index.html

本地賬號：tgadmin / Tgboot@123。

本地口令不要外帶

這組賬號來自本地初始化數據，只用於打開開發環境。 不要用於測試環境、生產環境，也不要把本地數據庫快照直接當成生產數據。

四、如果 AI 卡住了

讓 AI 按這個順序排查，並把完整報錯發回來：

現象優先檢查
後端啓動失敗數據庫是否啓動、3306 是否被佔用
登錄後接口 401Redis 是否在 127.0.0.1:6379 運行
Maven 找不到模塊是否在倉庫根目錄執行，是否保留 -am
端口衝突3306、6379、9999、9100 是否被舊進程佔用
前端請求失敗.env.development 的後端地址是否為 9999
RabbitMQ 連接失敗是否誤配了 spring.rabbitmq.*；開發環境默認使用嵌入式 Rabbit

只需給 AI 一句話

把“失敗步驟 + 完整錯誤 + 已經嘗試的修復”發給它，讓它繼續排查。 不要只發最後一行日誌，最早出現的 Caused by 通常才是根因。

五、人工兜底

只有在 AI 無法執行命令、或你明確想手動接管時，才需要看這一節。

git clone https://gitee.com/pub_module/tg-boot.git
cd tg-boot
powershell -ExecutionPolicy Bypass -File scripts\up.ps1

如果 .tools 缺少運行時：

powershell -ExecutionPolicy Bypass -File scripts\fetch-tools.ps1
powershell -ExecutionPolicy Bypass -File scripts\up.ps1

已有數據庫和 Redis 時，也可以單獨啓動後端：

powershell -ExecutionPolicy Bypass -File scripts\run-runner.ps1

這些命令只是兜底。正常路徑是：複製説明給 AI，讓 AI 執行並驗證。

六、下一步

環境起來之後，不要停在登錄頁。先讓 AI 做一次只讀分析，再進入真實模塊開發。
